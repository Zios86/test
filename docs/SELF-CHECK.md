# Самопроверка

Как проверялся каждый пункт. «Тест» — автоматический тест в `tests/FileOrganizer.Core.Tests`
(запуск: `dotnet test tests/FileOrganizer.Core.Tests`). «UI» — ручная проверка собранного `FileOrganizer.exe`
(запускался под Wine в Linux: анализ → «Навести порядок» → «Структура» → отключение «Только посмотреть» →
«Применить» → «История» → «Отменить»; после отката дерево файлов совпало с исходным).

## Критерии готовности

| Критерий | Как обеспечено | Проверка |
|---|---|---|
| Не теряет пользовательские файлы | «Удаление» = перемещение в папку восстановления; перемещение без перезаписи; между дисками — копия → проверка размера → удаление исходника, при ошибке копия убирается | Тесты `Execute_then_rollback_restores_exact_state` (сравнение SHA‑256 всех файлов до/после), `Never_overwrites_…`, `Replace_moves_existing_file_to_recovery_and_is_reversible` |
| Не перезаписывает без подтверждения | Конфликт проверяется при планировании и прямо перед операцией; по умолчанию «оставить оба» | `Never_overwrites_existing_file_even_if_it_appears_after_planning`, `Conflict_keep_both_skip_replace`, `Two_files_with_same_name_into_one_folder_get_unique_names` |
| Работает в режиме предпросмотра | Режим «Только посмотреть» включён по умолчанию, исполнитель в нём отказывается работать; планирование диск не трогает | `Simulation_mode_is_default_and_blocks_changes`, `Sort_by_type_moves_only_top_level_files_and_creates_folders` (снимок до/после планирования) |
| Пользователь понимает каждое изменение | У каждого действия — причина и уверенность; экран «Будет выполнено»; дерево «было/станет» | `Commercial_offers_from_spec_are_one_topic_with_explanation`, `Preview_trees_show_changes`; UI |
| Операции можно отменить | Журнал Pending/Done, откат пакета, последнего действия, «до момента» | `Execute_then_rollback_restores_exact_state`, `History_survives_restart_and_restore_to_point`, `Undo_last_and_rollback_conflict_keeps_both`; UI |
| Работа с большим количеством файлов | Обход без рекурсии, хеши только у файлов одинакового размера, параллельно, кэш; виртуализация списков и деревьев | Нагрузочный тест: 102 000 файлов — сканирование ≈ 0,6 с, поиск дубликатов ≈ 1,2 с, выполнение + откат 2 000 перемещений ≈ 4 с |
| История сохраняется после перезапуска | SQLite | `History_survives_restart_and_restore_to_point`, `Settings_rules_profiles_exclusions_persist` |
| Ошибка одного файла не останавливает обработку | try/catch на уровне каждой операции и каждого элемента сканирования | `One_failed_file_does_not_stop_the_rest`, `Access_errors_do_not_stop_scan` |
| Интерфейс отзывчив | Сканирование, анализ, выполнение, откат, поиск — в фоновых задачах с прогрессом | UI |
| Можно отменить сканирование | `CancellationToken` + кнопка «Остановить» | `Cancellation_stops_scan`, `Cancellation_mid_execution_keeps_journal_consistent_and_reversible` |

## Перечень проверок из постановки

| Проверка | Результат |
|---|---|
| Кириллица | ✅ Имена файлов и папок на кириллице во всех тестах; UI с путём `…\Загрузки` |
| Длинные пути (> 260) | ✅ `Handles_long_paths`, `Long_paths_move_and_rollback`; в манифесте `longPathAware` (в Windows также должна быть включена политика LongPathsEnabled) |
| Одинаковые имена | ✅ `Two_files_with_same_name_into_one_folder_get_unique_names`, `Rename_preview_was_becomes_with_conflicts` |
| Файлы без расширения | ✅ `Extension_parsing`, `Read_only_and_cyrillic_and_no_extension_files_are_moved_and_restored` |
| Скрытые файлы | ✅ `Skips_hidden_files_by_default_and_includes_on_request`; скрытый файл делает папку непустой (`Empty_folders_including_chains_and_junk_only`) |
| Read‑only файлы | ✅ Перемещаются и возвращаются (`Read_only_…`); при окончательном удалении атрибут снимается |
| Сетевые папки | ⚠ Поддерживаются UNC‑пути (`\\server\share`) средствами .NET; в тестовой среде сети нет — не проверено на реальном ресурсе. Между дисками/ресурсами используется безопасное копирование с проверкой |
| Нет доступа | ✅ `Access_errors_do_not_stop_scan` (на Linux не под root), сообщение «Нет доступа к N файлам» со списком |
| Файлы, открытые другими приложениями | ⚠ Ошибка совместного доступа перехватывается, операция помечается «Файл открыт в другой программе», остальные продолжаются; при копировании между дисками копия удаляется, если исходник занят. Сама блокировка в Linux не воспроизводится — проверено обобщённым тестом ошибок |
| Файлы > 10 ГБ | ✅ `File_larger_than_10_GB_is_scanned_bucketed_moved_and_restored` (11 ГБ, разреженный файл); хеширование потоковое, буфер 1 МБ |
| Каталоги со 100 000+ файлов | ✅ `Hundred_thousand_files_scan_analyze_plan_execute_rollback` (102 000 файлов) |
| Отмена операции | ✅ Сканирования и выполнения (см. выше); выполненная часть остаётся в журнале и откатывается |
| Аварийное завершение | ✅ `Crash_recovery_marks_pending_operations_by_actual_state`; глобальные обработчики исключений в приложении — ошибка показывается, программа продолжает работу |
| Восстановление после сбоя | ✅ При запуске Pending‑операции сверяются с диском, пакет помечается «Прерван» и откатывается |
| Откат | ✅ Побайтовое совпадение дерева после отката (SHA‑256 каждого файла) |
| Конфликт файлов | ✅ Оставить оба / пропустить / заменить (с сохранением старого) / сравнить |
| Защита системных данных | ✅ `System_paths_are_protected`, пропуск системных папок при сканировании, файлы с атрибутом System не трогаются, системный диск целиком (C:\) выбрать нельзя, а выбранная папка никогда не удаляется |

## Известные ограничения

* Значки интерфейса используют шрифт Segoe Fluent Icons / Segoe MDL2 Assets (есть в Windows 10/11).
* Похожие изображения (perceptual hash) — в плане развития.
* Корзина Windows: файлы, отправленные туда, восстанавливаются средствами Windows (программа об этом сообщает при откате).
