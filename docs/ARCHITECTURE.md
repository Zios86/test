с `IProgress<T>` и `CancellationToken` — интерфейс не блокируется, у каждой длительной операции есть «Остановить».

## 4. База данных (SQLite, `%LOCALAPPDATA%\FileOrganizer\fileorganizer.db`)

Режим WAL, внешние ключи включены. Схема создаётся автоматически (`Database.Migrate`), версия — в `schema_info`.

| Таблица | Поля | Назначение |
|---|---|---|
| `schema_info` | version | версия схемы |
| `settings` | key PK, value | настройки (`app` → JSON `AppSettings`) |
| `profiles` | id, name UNIQUE, is_active, settings_json, created_at | профили: Загрузки, Работа, Личные файлы, Фото, Архив, свои |
| `rules` | id, profile_id → profiles, name, enabled, priority, rule_json | правила конструктора |
| `exclusions` | id, profile_id → profiles, kind (Folder/Extension/File/Mask), pattern | «Не анализировать» |
| `hash_cache` | path PK, size, mtime_ticks, sha256, updated_at | кэш хешей: файл не перечитывается, пока не изменились размер и дата |
| `scans` | id, root, started_at, finished_at, file_count, folder_count, total_size, duplicate_count, duplicate_bytes, empty_folder_count, error_count, summary_json | итоги анализов |
| `batches` | id, title, root, recovery_folder, created_at, status, op_count | пакет изменений = одно нажатие «Применить» |
| `operations` | id, batch_id → batches, seq, kind, source, destination, old_name, new_name, status, error, reason, size, executed_at | журнал для отката |
| `tags` | id, name UNIQUE, color | виртуальные теги |
| `file_tags` | path, tag_id → tags (PK по обоим) | теги файлов (переезжают вместе с файлом при перемещении и откате) |
| `watched_folders` | id, path UNIQUE, enabled, last_checked | папки «Разобрать» (Inbox) |

Содержимое документов в базе не хранится.

## 6. Алгоритмы анализа

**Сканирование.** Обход без рекурсии (стек), по одной папке за раз. Не следует по символическим ссылкам и junction
(защита от циклов). Пропускает: системные папки (по имени в корне диска и по расположению — Windows, Program Files,
ProgramData, AppData, $Recycle.Bin, System Volume Information…), файлы с атрибутом «Системный», скрытые (по умолчанию),
исключения пользователя, папку `FileOrganizer_Recovery`. Ошибки доступа к папке/файлу собираются в `Errors` и не
прерывают обход. Прогресс — каждые 250 файлов; отмена — между файлами. Размеры папок считаются снизу вверх.

**Классификация по типу.** Таблица расширение → категория (Документы, Таблицы, Презентации, Изображения, Видео,
Аудио, Архивы, Установщики, Код, Временные, Прочее). Таблица редактируется в настройках.

**Умная классификация** (`SmartClassifier`), строго по приоритету источников:
1. правила пользователя (`RulesEngine`) — уверенность 100 %;
2. тип/метаданные файла — 95 % для «папки по типу»;
3. имя файла: нормализация (нижний регистр, ё→е, разделители → пробел, разбиение CamelCase/цифр) и тематические
   шаблоны (КП, договоры, счета, акты, отчёты, протоколы, инструкции, резюме, скриншоты, сканы, фото…).
   База 80 %; **+5 % за каждый соседний файл той же темы** (до +15 %); −20 %, если подходит под несколько тем;
4. содержимое (режим «Глубокий анализ»): первые ~8 000 символов TXT/DOCX/XLSX/PPTX/ODT/RTF/PDF — 60–80 % в зависимости
   от числа совпадений;
5. ИИ — только если тема не определена или уверенность ниже порога, только если включён; получает имя файла и
   ≤ 2 000 символов текста.

Каждый результат несёт список причин — они показываются как «Причина: …». Уровни: высокая ≥ 85 %, средняя ≥ 60 %,
низкая < 60 %. Автоматически отмечаются только высокие (порог настраивается).

**Похожие версии документов.** Базовое имя без пометок версий («(1)», final, new, копия, v2, цифры) — группа, если
имена разные и файлы не являются точными копиями. Не считаются дубликатами; есть окно сравнения текста.

**Пустые папки.** Снизу вверх: папка пуста, если на диске в ней нет файлов, кроме служебных (Thumbs.db, desktop.ini,
.DS_Store), нет пропущенных сканером подпапок (скрытых/исключённых) и все подпапки пусты. Показывается только верх
цепочки и длина цепочки. Служебные файлы при удалении уходят в папку восстановления.

**Крупные файлы.** Топ‑100, корзины >100 МБ/500 МБ/1/5/10 ГБ, распределение по категориям и по папкам первого уровня.

**Старые файлы.** По дате изменения (дата доступа в Windows ненадёжна). Предустановки 6 мес/1/2/3 года и свой период.

**Плохие названия.** Набор шаблонов (стандартные имена новых файлов, «Документ1», только цифры, имена камер, несколько
пометок версий, «копия», GUID, случайные строки). Предложение: `ГГГГ‑ММ‑ДД_<имя без шума>` или, если смысла не
осталось, `ГГГГ‑ММ‑ДД_<папка>_<номер>`. Автоматически ничего не переименовывается.

**Похожие папки.** Среди папок одного родителя: имя нормализуется (ё→е, без «новые/старые/копия/цифр/годов»);
одинаковые ключи → группа; приёмник — папка с наибольшим числом файлов; конфликты — одинаковые относительные пути.

**Возможно лежат не там.** В папке ≥ 5 файлов и ≥ 80 % одной категории — файлы другой категории предлагаются к переносу
в папку их темы (умная классификация).

**Временные файлы.** Расширения .tmp/.crdownload/.part/.bak, `~$` файлы Office, установщики старше 30 дней, архив
рядом с одноимённой папкой (уже распакован), «file (1).ext» того же размера, что «file.ext».

**Проектные группы.** Слова из имён (без стоп‑слов, ≥ 3 символов); слово, встречающееся у ≥ 3 файлов ≥ 2 разных
категорий, — кандидат в проект. Файлы → `Проекты/Проект_<слово>/{Документы|Данные|Презентации|Материалы|Архив}`.

## 7. Поиск дубликатов

```
все файлы (size ≥ 1 байт)
   │ группировка по размеру → только размеры, встречающиеся ≥ 2 раз
   ▼
файлы > 128 КБ: быстрый хеш SHA‑256 от первых и последних 64 КБ (параллельно)
   │ группировка (размер, быстрый хеш) → только группы ≥ 2
   ▼
полный SHA‑256 потоково, буфер 1 МБ из пула (параллельно, ≤ 4 потоков; результат — в кэш hash_cache)
   │ группировка (размер, SHA‑256)
   ▼
DuplicateGroup + рекомендация
```

Рекомендуемый экземпляр — с наименьшим «штрафом»: признаки копии в имени (+100: «(1)», copy, копия),
расположение в Загрузках/временной папке/«Дубликатах» (+50), глубина пути; при равенстве — более ранняя дата
изменения. Объяснение формируется из тех же признаков. Решение принимает пользователь: оставить все / новый /
старый / отмеченные вручную / переместить копии в «Дубликаты». Удаление всех копий невозможно.

Уровень 2 (похожие изображения, perceptual hash) — в плане развития (см. ROADMAP). Уровень 3 (похожие документы)
реализован как «похожие версии» без автоматических действий.

Производительность (Linux‑контейнер, 102 000 мелких файлов): поиск дубликатов ≈ 1,2 с; полный анализ — секунды;
повторный анализ использует кэш хешей.

## 8. Система правил

Правило = `ЕСЛИ <условия: все (И) | любое (ИЛИ)> ТО <переместить в папку | присвоить тег | не трогать>`.

Поля: расширение, тип файла, имя, имя без расширения, папка, размер (МБ), дата изменения, дата создания.
Операторы: =, ≠, содержит, не содержит, начинается с, заканчивается на, соответствует шаблону (маска `*.pdf` или
регулярное выражение с таймаутом 100 мс), одно из списка, >, <, старше N дней, новее N дней, раньше, позже.
Даты: «2024», «2024‑05», «17.05.2024». Папка назначения поддерживает `{year}`, `{month}`, `{category}`, `{ext}`.
Сравнение строк — без учёта регистра и с ё=е.

Примеры (кнопка «Примеры» в конструкторе):

```
ЕСЛИ расширение = pdf И имя содержит «счет»      ТО переместить в «Документы/Счета»
ЕСЛИ расширение = jpg И дата изменения раньше 2024 ТО переместить в «Фото/Архив/{year}»
```

Правила принадлежат профилю, выполняются по приоритету, срабатывает первое подходящее; имеют приоритет над
умной сортировкой. «Ручной режим» = только правила пользователя.

## 9. Механизм предпросмотра

`PlanBuilder` строит план, **не трогая диск**, и поддерживает его целостность:

* одна операция на файл (повторная попытка для того же файла игнорируется; решение можно изменить — `Remove`);
* недостающие папки добавляются как отдельные действия «Создать папку» (их тоже можно отключить; при отключении
  папки отключаются действия внутри неё, при включении действия — включаются нужные папки);
* путь назначения проверяется на существующие файлы **и** на пути, уже занятые другими действиями плана; при конфликте
  действие помечается, по умолчанию — «оставить оба» (`имя (2).ext`), пользователь может выбрать «пропустить» или
  «заменить» и сравнить файлы;
* файлы, которые уже на своём месте (в папке с подходящим названием), не трогаются;
* системные/защищённые пути не попадают в план;
* `Summary()` даёт сводку «Будет выполнено»; `PreviewTreeBuilder` строит деревья «как сейчас» (с цветными
  пометками) и «как будет».

## 10. Выполнение и откат

**Выполнение** (`OperationExecutor`), только если выключен режим «Только посмотреть»:

1. создаётся пакет `batches` (статус Running);
2. порядок: создание папок (от верхних к вложенным) → перемещения/переименования/«удаления» → удаление пустых папок
   (от вложенных к верхним);
3. перед каждой операцией: файл существует; исходный путь и путь назначения не системные и не защищённые;
   **запись Pending в журнал**; повторная проверка конфликта (файл мог появиться после анализа);
4. перемещение без перезаписи (`File.Move(overwrite:false)`); между дисками — копия во временный файл, проверка размера,
   переименование, удаление исходника (если исходник занят — копия удаляется, ничего не теряется);
5. запись Done/Failed с текстом ошибки; ошибка одного файла не останавливает остальные; «Остановить» — между
   операциями;
6. недостающие папки создаются с отдельной записью в журнал — при откате удаляются, если пусты;
7. «Заменить» = существующий файл сначала перемещается в `FileOrganizer_Recovery/<пакет>/Заменённые/` (тоже в журнал).

**Откат** (`RollbackManager`): операции пакета со статусом Done в обратном порядке:
перемещение/переименование/«удаление» → файл возвращается на исходный путь (если там уже есть другой файл — рядом,
с номером, и об этом сообщается); «создать папку» → удаляется, если пуста; «удалить пустую папку» → создаётся заново.
Теги переезжают вместе с файлом. «Отменить последнее действие» — последний не отменённый пакет;
«Восстановить состояние до…» — все пакеты после указанного момента, от новых к старым.

**«Удалить окончательно»** — отдельная команда для файлов пакета в папке восстановления, после двух предупреждений;
такие записи помечаются Purged, и откат честно сообщает, что их вернуть нельзя.

**Восстановление после сбоя** (при запуске): для пакетов в статусе Running каждая запись Pending сверяется с диском
(файл в новом месте и нет в старом → Done; в старом и нет в новом → Failed; оба → Failed с пометкой «проверьте копию»),
пакет помечается «Прерван» и может быть отменён как обычно.

## 11. ИИ

`IAIClassifier` — подключаемый интерфейс. Реализация `OllamaClassifier` обращается к `http://localhost:11434/api/generate`
с JSON‑ответом (тип документа, проект, клиент, тема, год, уверенность). Не локальный адрес используется только при
включённом согласии «Разрешить отправку во внешний сервис». В приложение ИИ попадает только из «Глубокого анализа»
и только для файлов, тема которых не определена правилами, именем или содержимым.

## 12. Журнал

`%LOCALAPPDATA%\FileOrganizer\logs\ГГГГ-ММ-ДД.log`, строка: время, уровень, операция, путь, результат, ошибка.
Содержимое документов не записывается.
